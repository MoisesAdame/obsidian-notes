## 1.2.1 Assemblers

- Originally you'd program writing 1's and 0's, but this was difficult.
- So the instructions were translated to **mnemonics** to be more readable.
- An **assembler** is the translator from mnemonics to machine language.
- The input for the assembler is the **source program** and the output is the **object program**

## 1.2.2 Loaders

### Generalities

- Initially the **assembler** could be in charge of placing the **object program** into the memory and executing it.
- But this is a waste of **memory**, thus loaders were created. Giving more memory to the user's program.
- Loaders are much smaller than assemblers.

### Subroutines

![[fig1.3.png|400]]
#### Generalities

- Instructions designed to be used by other routine to perform a task.
- There are two types: **Open** and **closed** subroutines
- **Open Subroutines:** Set into the main program every time is called.
- **Closed Subroutines:** Set outside the main program.

#### Use of loaders

- Initially the subroutine would be placed before the main program. But this led to **holes** or overlays as in the picture.
- Thus, the loader places the subroutine just before the main program. This is called **relocation**.
- The steps are the following:
	1. **Allocation:** Find memory space.
	2. **Linking:** Resolve references between object decks (every object program used).
	3. **Relocation:** Adjust the addresses used in the object decks so that they correctly correspond to their actual locations in memory
	4. **Loading:** Place machine language into the machine

## 1.2.3 Macros

- Used to **avoid** repeating yourself.
- You just have to **define an abbreviation** and the **macro processor** substitutes it.
- Each time there is a **macro call**, the **macro processor** substitutes it for the **macro definition**.

## 1.2.4 Compilers

- When we moved from assembly to high-level languages there was a need for **compilers** and **interpreters**.
- **Compilers:** Program that translates from high-level to object program.
- **Interpreters:** Program that translates and executes. 

## 1.2.5 Formal Systems

- An abstract system that has an **alphabet**, a set of **words** (axioms), and **rules of inference** (finite set of relations).
- They are useful for specifying the **syntax** and **semantics** of programming languages.
