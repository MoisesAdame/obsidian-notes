## 1. Introduction
In this chapter the MSA algorithms of **MAFFT**, **TBA** and **MAUVE** are explained. The fist one is very good, but assumes that the *order of aligned sites* is consistent. While the last two are *specialized for genome alignment*.

### 1.1 Basic Concepts
**Sequence alignment** is set of corresponding residues. The **interpretation** is that they have same *origin* and/or *functionality*.

### 1.2 MSA Strategies in MAFFT
#### 1.2.1 Progressive Method
This is the most widely used method, starts off with a *guide tree*. In the case of **MAFFT** it uses a *two cycle progressive method*, which is a progressive method, but repeated twice, called **FFT-NS-2**. In the other hand **FFT-NS-1** is the same but has one cycle, thus is *less accurate*.

The drawback of the progressive method is that if there are *incorrectly introduced gaps*, the gap is never removed. Although there are methods that improve accuracy. **Iterative refinement** and **consistency-based** methods.

#### 1.2.2 Iterative Refinement Method
It works by defining the **"goodness"** of the alignment and maximizing it. There have been many proposed functions being **WPS** the most successful, used in **FFT-NS-i** of MAFFT.

#### 1.2.3 Consistency-Based Iterative Refinement Method
The grading is based on **how consistent is on pairwise-alignments** and there have been many criteria proposed, being the most successful **TCOFFEE**.

## 2. Program Usage
The input and outputs are in **FASTA** format, and usually, it comes as a command line program.

### 2.1 A Large Number (>~1000) of Sequences - FFT-NS-2, FFT-NS-1, or PartTree
For large number of sequences the only option is **progressive method**, done with the following command:

For **two** cycle:
```MAFFT
% mafft input_file > output_file
```

For **one** cycle:
```MAFFT
% mafft --retree 1 input_file > output_file
```

If there are more than **10,000** sequences, FFT-NS-1 is slow, thus use **PartTree**:
```MAFFT
% mafft --parttree input_file > output_file (Two clycles)
% mafft --parttree --retree 1 input_file > output_file (One cycle)
```

### 2.2 Long Sequences (> ~10,000 nt.) - FFT-NS-2 or FFT-NS-i
If the sequence is long, take into account the **space complexity** and use the **FFT** algorithm.

For **progressive method**:
```MAFFT
% mafft input_file > output_file
```

For **iterative refinement method method** (10 maximum iterations):
```MAFFT
% mafft –-maxiterate 10 input_file > output_file
```

### 2.3 Low Similarity - E-INS-i, L-INS-i, or G-INS-i
First check if the sequence is *globally* or *locally* alignable, then consider the following cases.

- **Case a (long internal and terminal gaps):** Always assume this one. Use **E-INS-i**.
- **Case b (long terminal gaps):** Use **L-INS-i**.
- **Case c (globally alignable):** Use **G-INS-i**

For **E-INS-i** the command is:
```MAFFT
% mafft --genafpair --maxiterate 1000 input_file > output_file or
% mafft-einsi input_file > output_file
```

For **L-INS-i** is:
```MAFFT
% mafft --localpair --maxiterate 1000 input_file > output_file or
% mafft-linsi input_file> output_file
```

And for **G-INS-i** is:
```MAFFT
% mafft --globalpair --maxiterate 1000 input_file> output_file or
% mafft-ginsi input_file> output_file
```

### 2.4 Adding New Sequence(s) to an Existing Alignment
#### 2.4.1 Profile-Profile Alignement
This can be done converting a sequence or alignment into a **profile** and then applying a **profile-profile alignment algorithm**, as with mafft:
```MAFFT
% mafft-profile aligned_group1 aligned_group2> output_file
```

### 2.5 Outputting a Guide Tree
When we want just the **guide tree** and the number of sequences is **below 500** we can use (it doesn't matter if we use --localpair, --globalpair or --genafpair):
```MAFFT
mafft --retree 0 --treeout --globalpair input_file > output_file
```

If the number of sequences is **above 500** we should use:
```MAFFT
% mafft --retree 0 --treeout --6 merpair input_file> output_file
```

### 2.6 Genome Alignment
As we said, for this alignment MAFFT is not suitable, and we should use **TBA** or **MAUVE**.

For **TBA** the fist step is to align pairs of genomes with **BLASTZ**, being the output, TBA's input. As well we have to input a binary tree of genomes, that indicates the order of the *progressive alignment*. **TBA** can also be used for aligning multiple sequences, but with respect to a given **genome**.

In the other hand **MAUVE**, the advantage is that it doesn't require BLASTZ.
