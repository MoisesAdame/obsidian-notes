## 1. Introduction
### 1.1 An Introduction to Nucleotide Databases
Genetics tries to find relations between **phenotypes** and **genetic variations**. But recently, finding this relations has become easier using digital data.

### 1.2 International Nucleotide Sequence Database Collaboration: DDBJ, EMBL and GenBank
In the **1980's** the US, Europe and Japan started constructing databases for storing sequences with the NCBI, EMBL and the DDBj. Util joining forces under the name of **International Nucleotide Sequence Database Collaboration (INSDC)**.

Right now they have more than **80 billion base pairs**, and this number every year grows due to the faster rate of sequencing.

### 1.3 Other Nucleotide Sequence Databases
Additionally to those databases, there have been a lor more created, but sometimes due to *lack of quality*, they are not taken seriously. 

## 2. Program Usage
### 2.1 Database File Formats
#### 2.1.1 FASTA Format
The *simplest* of them all. Originally used for the **Pearson & Lipman's FASTA algorithm**.

#### 2.1.2 Flat File Format
GenBak, EMBL and DDBJ each have their own.

#### 2.1.3 Accession Numbers, Version Numbers, Locus Names, Database Identifiers, etc.
- **Accession Number:** The id of the sequence. A string of *two* characters and *six* digits.
- **Version:** Incremental number. The number of changes to that sequence.
- **Locus Names:** Older identifiers. Group entries with similar sequences, but *not generally used*.
- **Database Identifiers:** *Two* or *three* character strings that represent where the sequence was originally submitted (gb for GeneBank, emb for EMBL, dbj for DDBJ, etc.)

### 2.2 Smith-Waterman and Dynamic Programming
This is an algorithm that uses *dynamic programming* and a *matrix* in order to find *local alignments*. In order to fill up the matrix, they use recursion, assigning scores if there are neighbors.

Finally, once you have the matrix, you just have to find the largest score, and move upward-left until finding a zero. Considering the previous, it is important to note that there are many *paths* and thus, many *alignments*.

### 2.3 Weighting/Models
#### 2.3.1 PAM Matrices
Due to the fact that assigning scores in the previous algorithm is done via unknown weights (you have to define them), they created a **Accepted Point Mutation (PAM) matrices**, that uses observed data.

These matrices are pretty old and biased, due to their creation in the **1970's**.

#### 2.3.2 BLOSUM Matrices
These matrices were created to outperform **PAM matrices** in the **1990's**, additionally, they are based on the BLOCKS database, where proteins are organized into blocks with the same motifs. 

The way they were made, makes them more *robust* and *accurate*.

#### 2.3.3 Choosing a Matrix
Depending on the task is the matrix we have to choose:
- **PAM Matrices:** Used for closely related protein sequences.
- **BLOSUM Matrices:** Used for highly distant protein sequences.

### 2.4 BLAST Programs
When performing a search **nucleotide-nucleotide** is beneficial because *no info is lost*. Conversely, due to the fact that there are only *4 bases*, the probability of a match increases, as opposed to the use of the *20 amino acids*, which show more common ancestry.

The **Basic Local Alignment Search Tools (BLAST)** are very accurate and have different forms:
- **Nucleotide BLAST (blastn):** Compare nucleotide query against a nucleotide database.
- **Protein BLAST (blastp):** Compare protein query against a protein database.
- **blastx:** Compare nucleotide query (translated in the 6 reading frames) against a protein database.
- **tblastn:** Compare a protein query against a nucleotide database (translated in the 6 reading frames).
- **tblastx:** Compare nucleotide query (translated in the 6 reading frames) against a nucleotide database (translated in the 6 reading frames).

BLAST is an *heuristic* algorithm, and works *separating the sequence in words* and finding their *neighbors*, if a neighbor is found, the algorithm tries to find *extensions*.

### 2.7 BLAST Search Parameters
#### 2.7.1 Max Target Sequences
The number of sequences displayed in the results.

#### 2.7.2 Short Queries
Short queries imply lots of results, check **short query box** to ajust parameters.

#### 2.7.3 Expect Threshold
Just display matches with lower $E()$ values.

#### 2.7.4 Word Size
The **length of the word** used in the BLAST algorithm. The *bigger* the word, the *faster* the time, but resulting in *lower sensitivity*.

#### 2.7.5 Scoring Parameters
These are the **match and mismatch scores**. The *greater* the expected divergence, the *larger* the ratio we should use.
