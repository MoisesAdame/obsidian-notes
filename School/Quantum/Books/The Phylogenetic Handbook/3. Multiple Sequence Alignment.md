## 3.1 Introduction
An alignment is an **homology hypothesis** either abour *proteins* or *nucleotides*. Thus, aligned sequences are assumed to come from a common place.

Not all the alignments have **the same length**, and thus, to align multiple sequences wi have to add hyphens (-). These hyphens represent **deletions**, **insertions** or a **combination of them**.

Alignments are an essential task, and are a **prerequisite** for any phylogenetic analysis.

## 3.2 The Problem of Repeats
A factor that increases alignment difficulty are **repeats**, sections in the same sequence that are similar with each other.

One way to solve this is making a **phylogenetic analysis** of all the repeats in the sequence. But the results are not always *satisfactory*.

## 3.3 The Problem of Substitutions
Substitutions are when nucleotides change, when they are a few there are no problems, but when the **sequence identity** (identical pairs / aligned positions) drops below certain values, it becomes *difficult* to find a *good alignment*.

When analysing sequences, there are a few **substitution patterns** to take into account:
1. Substitutions are not evenly distributed, there are **blocks** with very few substitutions. (This makes it *easier* for algorithms to find alignments, it is due to the *presence of essential regions*).
2. Aligned pairs are **biochemically similar**. The most important property conserved is *polarity/hydrophobicity*.

How biochemically similar two sequences are can be seen using the PAM or BLOSUM matrices as seen in the **section 2.3** of [[1. Similarity Searching Using Blast]]. For instance, the higher the biochemical similarity, the *higher the weight*.

It is important to state that in **nucleotide sequences** is much more difficult to detect if the substitutions are *conservative* or not. That is why if it is possible, we should align *protein coding sequences at the amino acid level*.

## 3.4 The Problem of Gaps
When there is divergence **indels** (deletions and insertions) accumulate over time. Often algorithms don't distinguish among them.

If they didn't exist, we would just need to slid the sequences one on top of another until finding the best alignment, but due to their existence, we use **dynamic programming**. Additionally, their presence is penalized with the following formula:
$$
GP = g + e(l-1)
$$

Often, the values of that formula are selected **arbitrarily**, but it is used because it works well. Sometimes even gaps being **unpenalized**.

### 3.5.2 Dynamic Programming
This approach manages to score pairs and penalize gaps with a **complexity of $O(N^{2})$**. The steps it uses are the following:
1. Fill the matrix using a BLOSUM or PAM matrix. If there are gaps, set the penalty.
2. Thence we calculate the subpath using the following recursive function.

$$
F(i, j) = \text{max}
\begin{cases}
F(i - 1, j - 1) + s(X_{i}, Y_{i}) \\
F(i - 1, j) - g \\
F(i, j - 1) - g \\
\end{cases}
$$
Where we consider:
- **Substitution:** $(X_{i}, Y_{i})$ moves from (i - 1, j - 1) to $(i, j)$
- **Indels:** Insertion in X (or deletion in Y) moving from $(i - 1, j)$ and insertion in Y (or deletion in X) moving from $(i, j - 1)$.
- Where $s(X_{i}, Y_{i})$ is the score given by the BLOSUM matrix.

3. Construct the best alignment, using treaceback.

## 3.6 Multiple Alignment Algorithms
To align multiple sequences we can use dynamic programing which yields a **complexity of $O(N^{M})$**. Although the task can be expressed as minimizing the **weighted sum of pairs function**, as shown below:
$$
\sum_{i}\sum_{j}W_{ij}D_{ij}
$$

Where $D_{ij}$ is the *score between each pair of sequences* and $W_{ji}$ is a *weight*, which by default is 1.

There are many other solutions, but all of them have limitations, thus, we'll discuss heuristics or approximate alternatives.

### 3.6.1 Progressive Alignment
This type of alignment is done by first, creating an *approximate phylogenetic tree* of the sequences. Having that, the algorithm performs *pairwise alignment using dynamic programming* scaling up until reaching the root.

The most commonly used software for this is **CLUSTAL** either in the *CLUSTALW* or *CLUSTALX* versions.

### 3.6.2 Consistency-Based Scoring
This algorithm is better than **progressive alignment** because progressive alignment cannot correct initial errors such as *incorrect tree topology* or *simple errors in the early alignments*. 

Thus instead of computing the pairwise alignments of the branches, it does this for all the leaves, selecting the one with the **best WSP function**.

The software used for this is **T-COFFEE**. The drawback is that it is slow, but is more accurate than CLUSTAL.

### 3.6.3 Iterative Refinement Methods
This method consists of grouping *randomly* all the sequences in pairs, then they are aligned using *dynamic programming*.

This is done in *many iterations* until the score converges.

Although the original programs were **PRRN**, they were not used a lot. Recently, algorithms such as **MAFFT** and **MUSCLE** were developed under the same idea but with novel methods.

### 3.6.4 Genetic Algorithms
One software that uses these type of algorithms is **SAGA**, which replaces them instead of the *dynamic programming*. Unfortunately it is very slow, and due to the fact that is *stochastic* it doesn't always yields the same results.

### 3.6.5 Hidden Markov Models
HMM's are based on probabilistic models, they are used for many things, and although they were inaccurate the **SAM** method is comparable to **CLUSTAL**, but slower.

### 3.6.6 Other Algorithms
One of them is **divide and conquer**, that uses the WSP scoring function finding alignment sections that joined, give the best alignment.

**Posterior probability** mixes consistency based progressive alignment with HMM's. One example is **PORBCONS**.

## 3.7 Testing Multiple Alignment Methods
Testing a method can be difficult, sometimes authors use particular parameters that favor their performance. The best thing to do is to use data sets *generated by experts* like **BALIBASE**.

BALIBASE is a collection of *well-documented* alignments for many situations such as equidistant sequences, orphan sequences, two families and long insertions.

## 3.8 Which Program to Choose?
Although accuracy is a major concern, *execution time* and *memory usage* are very important. The program you use might depend on the number of sequences.

Once we have the results, we can use the **ALTAVIST** web server to compare them.

## 3.9 Nucleotide Sequences vs. Amino Acid Sequences
Nucleotide sequences can be *coding* (generate proteins) or *non-coding*. 

If the sequences are closely related, we would tend to use *nucleotide sequences*, conversely if they are distantly related *amino acid* sequences would be better.

If the sequences are *coding*, it is better to carry **nucleotide alignment**. It is important to note that *non-coding* sequences, after a lot of divergence, might be difficult to align.

## 3.10 Visualizing Alignments and Manual Editing
Manually refined methods are **superior** tu purely automated ones. This is because it is necessary to correct *obvious alignment errors*.

Sometimes it is necessary to introduce gaps to maintain a correct alignment. But depending on the used method, is how this gaps will be handled.

There are a lot of programs that can be used to visualize, and edit sequences, some of which are presented in the book.

## 3.16 Editing and Viewing Multiple Alignment
The alignment will be done in the **amino acid level**. This is done using **SE-AL** in mac. And we'll use it to delete ambiguously aligned regions in the coding gene based on the ALTAVIST results.

Steps:
1. Alignment > Use Block Colors
2. Amino acid translation: Alignment > Alignment Type > Amino Acid
3. Delete ambiguity regions such as column range 47-52: Select > Edit > Cut
4. Repeat the same process for column range 89-90.
5. Repeat the same process for column range 47-52, 326-362, 403-408 and 425-511.
6. Save the alignments: Save as > Export

In this case we only *deleted  unreliable regions*, which is the most common task in sequence editing.
