## Ingeniería de Requerimientos
### Conceptos de la Ingeniería de Requerimientos
#Q  #AOSR/2igb2
- La ingeniería de requerimientos es el proceso de establecer :: Los **servicios** que quiere el **cliente**. #AOSR/2igb2/s/1ugb
- En la ingeniería de requerimientos también se describen las :: Restricciones del software. #AOSR/2igb2/s/4g15
- Los requerimientos del sistema son las :: Descripciones de los **servicios** y **restricciones**. #AOSR/2igb2/s/stkc
- Los **pasos** de la Ingeniería de Software son :: a) Elicitación b) Especificación (SRS) c) Validación d) Administración #AOSR/2igb2/s/5bt2
- Stakeholder del sistema es toda :: Persona que se ve **afectada** por el sistema. #AOSR/2igb2/s/2i4j
- Durante el ciclo de vida de software el problema más caro y difícil de corregir es el de :: Errores de Requerimientos. #AOSR/2igb2/s/19im
- Para evitar el problema de tener errores en los requerimientos una buena práctica es :: Obtenerlos y definirlos bien desde un inicio. #AOSR/2igb2/s/hskk
- Hay diferentes formas de clasificar los requerimientos de software, algunas son :: Nivel de detalle, naturaleza y prioridad. #AOSR/2igb2/s/z566

#### Requerimientos No Funcionales
#Q  #AOSR/764rr
- Son las... y... del sistema :: Características generales, restricciones operativas. #AOSR/764rr/s/69e8
- Es difícil definirlos porque son de :: Libre interpretación. #AOSR/764rr/s/4j3q
- Para ello se recomienda definirlos :: De forma **cuantitativa**. #AOSR/764rr/s/48q7
- **Sommerville** propone dividir los requerimientos funcionales en 3 :: De producto, de organización y externos. #AOSR/764rr/s/fdoe
- Se documentan en forma de :: Narraciones.

##### Clasificación
#Q
- Los NFR de **producto** son los que dicen como debe :: Actuar el software.
	- Los 4 NFR de **producto** son: *Eficiencia* (velocidad, memoria), *confiabilidad* (tasa de fallas), *usabilidad* y *seguridad*.
- Los NFR de **organización** son los que se derivan de las... ya sea del... o del... :: Políticas, cliente, desarrollador.
	- Los 3 NFR de **organización** son :: *Operacionales* (como se usará sistema), *de desarrollo* (cosas como lenguaje de programación) y *ambientales* (estándares y dónde vivirá el sistema) 
- Los NFR de **externos** son todos los requerimientos provenientes de factores... al sistema y su proceso de... :: Externos, desarrollo.
	- Los 3 NFR **externos** son :: *Regulatorios* (los que tienen que ser aprobados por regulador), *legislativos* (siga leyes) y *éticos* (sea aceptable por público general).

##### Métricas para su Especificación
#Q 
- Son 6 y son :: Rapidez, tamaño, facilidad de uso, fiabilidad, robustez y portabilidad.
- Ejemplo de **rapidez** :: Tiempo de regeneración de pantalla.
- Ejemplo de **tamaño** :: Cuánto pesa el proyecto (GBs).
- Ejemplo de **facilidad de uso** :: Tiempo de capacitación.
- Ejemplo de **robustez** :: Tiempo de reinicio después de falla.
- Ejemplo de **portabilidad** :: Número de sistemas objetivo.

### Características de los Requerimientos
#Q 
- Son las **propiedades** que hacen que un requerimiento se considere :: Maduro.
- Son 6 y son (NCCCNV) :: Necesario, conciso, completo, consistente, no ambiguo y verificable.
- **Necesario** es que si no está :: Hay consecuencias.
- **Conciso** es que es fácil de :: Leer y entender.
- **Completo** es que no necesita más :: Detalles.
- **Consistente** es que a otros requerimientos no los :: Contradice.
- **No ambiguo** es que solo tiene :: Una interpretación.
- **Verificable** es que se puede :: Cuantificar.
