## Proceso de la Ingeniería de Requerimientos
### Introducción
#Q
- Para **iniciar** un proyecto de software hay que identificar :: Una **necesidad** del negocio.
- Es la disciplina encargada de desarrollar :: Especificaciones maduras.
- Las especificaciones maduras, sirven para :: Generar acuerdos entre **stakeholders**.
- Las **partes** de la ingeniería de requerimientos son :: Elicitación, especificación, validación y administración.
- Nos da el mecanismo para entender :: Lo que **quiere** el cliente.
- Es un proceso :: Iterativo.

### Partes
#### 1 Elicitación
#Q 
- Se da al principio del :: Proyecto.
- Aquí es cuando se debe conocer lo que se :: Desarrollará
- Tiene 4 partes que son :: Concepción, indagación, análisis de requerimientos y negociación.

##### 1.1 Concepción
#Q 
- Se logra entender... el producto :: Como sirve
- Identificas a los... y los métodos de... :: Involucrados, comunicación.

##### 1.2 Indagación
#Q 
- En el proceso debes de :: Sumergirte
- Tomando en cuenta el proceso, puedes hacer el... del negocio :: As-is
- También hay que hacer un **estudio de factibilidad** tomando en cuenta recursos como :: Humanos, tecnológicos, financieros, etc.

###### Estudio de Factibilidad o Reporte de Viabilidad
#Q 
- Se inicia con un conjunto de requerimientos :: Comerciales preliminares.
- Describe como el sistema **respalda** procesos :: Comericales
- El resultado es un... que dice si software se debe o no... :: Software, implementar.

##### 1.3 Análisis de Requerimientos
#Q 
- Es la parte en que se crean los :: Casos de Uso.
- Los casos de uso, también se llaman :: Escenarios de usuario.
- Los casos de uso, describen la forma en que... interactúa con... :: Usuario, sistema.
- En esta etapa, también se identifican los requerimientos de :: Usuario y sistema.

##### 1.4 Negociación
#Q 
- Se usa cuando el... pide más de lo que se puede... :: Cliente, lograr.

#### 2 Especificación
#Q 
- Es la etapa donde se... los requerimientos de... y de... :: Redactan, usuario, sistema.
- Los requerimientos se escriben como..., donde cada una tiene una... y un tiempo de... :: Historias de usuario, prioridad, fin.
- Esto se hace en el documento de... cuyo nombre formal es... :: requerimientos, SRS-IEEE830.
- El SRS sirve como... entre... :: Contrato, desarrollador y cliente

#### 3 Validación
#Q 
- Consiste en volver a :: Revisar requerimientos.
- Se revisan los requerimientos para ver que no haya :: Ambigüedades, inconsistencias u omisiones.
- En esta fase esta involucrado :: Todo el equipo.
- Al terminar la fase, el usuario tiene que :: Firmar.

#### 4 Administración
#Q 
- Se les da seguimiento a los... y a sus... :: Requerimientos, cambios.

## Descubrimiento de Requerimientos
### Introducción
#Q 
- Es el proceso donde se interactúa y recopilan los... de las partes... :: Requerimientos, interesadas.
- Sirve para que los interesados comprendan como :: Será el sistema.
- Algunos de los métodos que se pueden usar son :: Entrevistas, casos de uso, escenarios, prototipos, etc.

### Entrevistas
#Q 
- Se obtiene información mediante el... en un encuentro formal y... :: Diálogo, planeado.
- La información que salga de ellas se debe... de tal manera que sea útil :: Transformar.
- Hay tres tipos de entrevistas :: Estructuradas (preguntas definidas), no estructuradas (preguntas improvisadas) y mixtas.

### Casos de Uso y Escenarios
#Q 
- Los casos de uso y los escenarios son técnicas... pero generalmente se usan... :: Diferentes, juntas.
