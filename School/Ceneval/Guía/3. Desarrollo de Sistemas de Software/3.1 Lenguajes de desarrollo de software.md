## Lenguajes de Programación
### Definición
#Q  #AOSR/6d0d6
- Es un **formalismo artificial** en el que se pueden expresar :: Algoritmos. #AOSR/6d0d6/s/1d29
- Es un conjunto de... que permiten asociar a cada programa correcto un... :: Reglas, cálculo. #AOSR/6d0d6/s/5mve
- No tienen :: Ambigüedades. #AOSR/6d0d6/s/7t1c

### Niveles de Descripción
#Q  #AOSR/7vtm3
- Un lenguaje se puede describir en **3 áreas** que son :: Gramática, semántica y pragmática. #AOSR/7vtm3/s/6c0j
- En computación hay un **4to nivel** que es :: Implementación. #AOSR/7vtm3/s/8dbd

#### Gramática
#Q  #AOSR/5m9a2
- Responde a la **pregunta** :: Qué frases son correctas. #AOSR/5m9a2/s/2lga
- Necesita un **alfabeto $\sum$** que es un :: Conjunto *finito* de *símbolos*. #AOSR/5m9a2/s/1gfs
- Necesita un **componente léxico** que nos dice que :: Secuencia de símbolos forman **tokens**. #AOSR/5m9a2/s/43fs
- Necesita una **sintaxis** que nos dice la secuencia de :: Palabras que hacen *frases legales*. #AOSR/5m9a2/s/49t9

#### Semántica
#Q  #AOSR/2uas3
- A cada frase correcta le da :: Un significado. #AOSR/2uas3/s/7sg9

#### Pragmática
#Q  #AOSR/g4sa5
- A una frase con significado le da :: Un uso. #AOSR/g4sa5/s/7j70

#### Implementación
#Q  #AOSR/19i5m
- Tenemos que **describir** como ejecutar una... de tal modo que respete... :: Oración correcta, semántica. #AOSR/19i5m/s/k5o1

### Gramática y Sintaxis
#### Alfabeto, Cadenas y Lenguaje Formal
#Q  #AOSR/4tu7c
- **Alfabeto ($A$)** es un :: Conjunto finito de símbolos. #AOSR/4tu7c/s/5qs9
- **Cadenas finitas ($A^{*}$)** es :: $A^{*} = \{ x | x_{1},x_{2},x_{3},\dots,x_{n} \in A, n \in \mathbb{N} \}$. #AOSR/4tu7c/s/z596
- **Lenguaje Formal sobre A($L \to A$)** es :: $L \subset A^{*}$. #AOSR/4tu7c/s/575f

#### Gramática Libre de Contexto
#Q #AOSR/svjlj
>[!CONTEXT FREE GRAMMAR]
? #AOSR/svjlj/m/70hb
>$G = (NT, T, R, S)$ donde:
>1. $NT:$ Non Terminal Symbols Set
>2. $T:$ Set of finite symbols.
>3. $R:$ Set of rules.
>4. $S:$ Initial Symbol. $S \in NT$

#Q #AOSR/3ga61
>**Escribe una CFG que describa las operaciones aritméticas \+, \* & \-
? #AOSR/3ga61/m/74nl
>$G = (\{ E, I \}, {a, b, +, *, -, (, ) }, R, E)$
>Donde R es:
>1. $E \to I$
>2. $E \to E * E$
>3. $E \to E + E$
>4. $E \to E - E$
>5. $E \to -E$
>6. $E \to (E)$
>7. $I \to a$
>8. $I \to b$
>9. $I \to Ia$
>10. $I \to Ib$

#Q  #AOSR/2todb
>[!DERIVATION]
? #AOSR/2todb/m/6qk1
>Given $G = (NT, T, R, S)$ and $v, w \in NT \cup T$ we say that $v \implies^{*} w$ $w$ is derived from $v$ if:
>There exists a sequence of finite derivations $v \implies w_{0} \implies w_{1} \implies \cdots \implies w$

#Q 
>[!GENERATED LANGUAGE]
>The language generated by the grammar $G = (NT, T, R, S)$ is the set:
?
>$\mathcal{L}(G) = \{ w \in T^{*} | S \implies^{*} w\}$

#Q 
>[!Ambiguity]
>A grammar $G$ is ambiguous if:
?
>$\exists v \in \mathcal{L}(G) \text{that admits more than one derivation tree}$

#Q 
>[!Admitting a Derivation Tree]
?
>A string $v$ admits derivation tree $T$ if $v$ is the result of a
>Left to right traversal of derivation tree $T$.

#Q 
- Para un definir un lenguaje de programación una gramática **ambigua** es :: Inútil.
- Una **gramática ambigua** es inútil porque no sirve para :: Compilar.

### Limitaciones Sintactico-Contextuales
#Q 
- A veces la **corrección sintáctica** depende del :: Contexto.
- Por ello según el contexto algunas cadenas pueden ser legales o no a pesar de ser :: Correctas con respecto a la **gramática**.
- La **naturaleza contextual** de las **limitaciones sintácticas** hace que sean imposibles de describir usando una :: Gramática libre de contexto.
- Para poder describir **limitaciones sintácticas** vale la pena usar :: Gramáticas contextuales.
