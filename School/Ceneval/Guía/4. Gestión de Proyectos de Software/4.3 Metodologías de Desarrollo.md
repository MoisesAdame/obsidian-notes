## Metodologías de Desarrollo
### Metodologías Clásicas
#### Cascada
##### Generalidades
#Q 
- Orden es :: Secuencial, lineal.
- Para **pasar a la siguiente** fase, primero hay que :: Acabar por completo una.
- Se apoya en una extensa... y... :: Documentación, revisiones formales.
- Si hay **cambios** tienes que :: Regresar a etapa anteriro.

##### Ventajas
#Q 
- Cada fase tiene mucha :: Estructura y claridad.

##### Desventajas
#Q 
- El **software se libera** hasta que :: Todas las fases **terminan**.
- Conforme más avanzas los **cambios** :: Se vuelven más caros.
- El riesgo es elevado si :: Los **requerimientos** no son buenos.

##### Cuándo usar?
#Q 
- Proyectos con requisitos :: Claros y estables.
- Proyectos donde la **documentación** y las **revisiones** son :: Necesarios.
- Proyectos muy... y con procesos... :: Grandes, bien definidos.

#### Prototipado
##### Generalidades
#Q 
- Permite **evaluar** y **validar** la idea de forma :: Temprana.
- Ideal para **representar** los :: Requerimientos.
- Ideal si se **combina** con estrategia :: Iterativa.

##### Ventajas
#Q 
- Facilita la :: Comunicación.

##### Desventajas
#Q 
- Ciertas partes se tienen que :: Rehacer.
- Puedes perder la :: Visión global del producto.

##### Cuándo usar?
#Q 
- Cuando **requerimientos** :: No son claros o pueden evolucionar.
- Cuando es necesario validad la :: Experiencia de usuario.

#### Incremental
##### Generalidades
#Q 
- El proyecto se divide en... o partes... :: Miniproyectos, funcionales.
- Lo **primero en construirse** son los :: Requisitos principales.

##### Ventajas
#Q 
- Al **dividir el proyecto** se :: Reduce el riesgo.
- Se hacen entregas... que pueden desde muy temprano... :: Parciales, evaluarse.

##### Desventajas
#Q 
- Requiere una muy buena... para... los elementos :: Planeación, integrar bien.
- Dificultad al definir... al... :: La arquitectura, inicio.

##### Cuándo usar?
#Q 
- Proyectos muy... donde se quiere entregar... de forma... :: Complejos, funcionalidad, gradual.

#### Rapid Application Development (RAD)
##### Generalidades
#Q 
- Logra esa **rapidez** usando :: Iteraciones frecuentes.
- Requiere participación activa de :: Usuario.
- Puede usar... y es... :: Prototipos, iterativos.

##### Ventajas
#Q 
- Velocidad de entrega :: Muy rápida.
- Durante el proceso es fácil :: Ajustar requerimientos.

##### Desventajas
#Q 
- No es bueno para :: Proyectos grandes.
- Puede sacrificar aspectos de :: Calidad.

##### Cuándo usar?
#Q 
- Proyectos con plazos :: Muy cortos.
- Aplicaciones donde la interacción del usuario es :: Fundamental.
