## Pruebas de Software
### Introducción
#Q
- Son métodos para **encontrar** :: Defectos de software.
- Son procesos usados para :: **Medir** la calidad de software.
- Sirven para **verificar** que software :: Funcione correctamene.

### Niveles de Prueba
#Q
- Los **4 niveles** de pruebas son :: Unitario, integración, sistema y aceptación.

#### Pruebas Unitarias
#Q 
- Se hacen por :: Desarrollador.
- Se hacen de forma :: Individual.
- Corregir errores aquí es :: Barato.
- Usan métodos de :: Caja blanca.

#### Pruebas de Integración
#Q 
- Comprueba la interacción entre... a la hora de... :: Componentes, integrarlos.
- Se hacen por :: Developers o testers.
- Usan métodos de :: Caja blanca y negra (más común).

#### Pruebas de Sistema
#Q 
- Es el comportamiento de :: Todo el sistema.
- Prueban dos cosas :: RF y NFR
- Se prueba que los RF sean :: Cumplidos y seguros.
- Se prueba que los RNF tengan :: Usabilidad, eficiencia y velocidad.
- Se prueban desde el punto de vista de :: Usuario.
- Usan métodos de :: Caja negra.

#### Pruebas de Aceptación
#Q 
- Verifican **conformidad** de sistema con :: Requerimientos de contrato.
- Los **2 tipos** que hay son :: $\alpha$ y $\beta$.
- $\alpha$ testing se hace por :: Miembros internos.
- $\beta$ testing se hace por :: Miembros externos.

### Tipos de Pruebas
#Q 
- Los **4 tipos** de pruebas son :: Funcionales, no funcionales, estructurales y relacionadas a cambios.

#### Pruebas Funcionales
#Q 
- **Niveles de prueba** en que se aplican :: Todos.
- Su otro nombre es :: Caja negra.
- Verifican requerimientos :: Funcionales.
- Se aplican sobre la :: Interfaz del programa.
- No necesitas conocer la... solo las... :: Lógica, funciones.

#### Pruebas No Funcionales
#Q 
- **Niveles de prueba** en que se aplican :: Todos.
- Su **objetivo** es saber como el sistema :: Funciona.
- Las **6 características** que prueban (VERRUC) son :: Volumen, estabilidad, robustez, rendimiento, usabilidad y carga

#### Pruebas Estructurales
#Q 
- **Niveles de prueba** en que se aplican :: Todos (pero más en **unitario**).
- Su otro nombre es :: Caja blanca.
- Se **basan** en un minucioso :: Análisis de código.
- Para hacerlas tienes que **entender** :: La **lógica** del programa.

#### Pruebas Relacionadas a Cambios
#Q 
- Buscan **repetir** prueba de función que :: Previamente se verificó.
- Hay de **2 tipos** :: Confirmación y regresión.
- Las de **confirmación** se hacen cuando... y quieres ver si... :: hubo error, se corrigió.
- Las de **regresión** se hacen cuando se hizo un... y buscan ver si eso... :: Cambio en el proyecto, produjo error.

### Tipos de Técnicas
#Q 
- Los **2 grupos** que hay son :: Dinámicas y estáticas.
- Estas técnicas se **usan** para diseñar :: Casos de prueba.

#### Técnicas Dinámicas
#Q 
- Pueden ser de :: Caja negra o blanca.
- Tienen que ver con :: Ejecutar código.

#### Técnicas Estáticas
#Q 
- Consisten en... un objeto de prueba :: Analizar.
- No necesitan :: **Ejecutar** código.
- Tipos de objetos de pruebas :: Código, mock up, requerimientos.

### Diseño de Casos de Prueba
#### Introducción
#Q 
- Un caso prueba es un conjunto de de acciones que se ejecutan para... de un software :: Verificar características o funciones.
- Se basa en el estándar :: IEEE/ISO 29119.
- Es una **tabla** que tiene cosas como :: Número, id, descripción, entradas y respuestas esperadas.
- Para **escribirlos** no asumir... ni... de aplicación y apegarse a... :: Funcionalidad, características, SRS.
- Hay que asegurar la mayor... por lo que hay que hacer casos para... :: Cobertura, todos los requerimientos.
- Los casos de prueba deben de ser... ósea que siempre den el mismo... :: Autónomas, resultado.
- Como **no es posible** verificar todas las... implementar... :: Condiciones, técnicas de prueba.

##### Técnicas de Prueba
#Q 
- Las dos principales técnicas son :: Partición de equivalencia y análisis de valores límite.

###### Partición de Equivalencia
#Q 
- Divide rango de valores en... porque tienen el mismo... :: Grupos iguales, comportamiento.
- Se puede aplicar a... y es su tipo de prueba es... :: Todos los **niveles de prueba**, caja negra.
- Primero se hay que **definir** las... luego cada una se **define** como... :: Particiones, válida o inválida.
- La **hipótesis** es que si un valor de la partición... los demás... :: Pasa o no pasa, se comportarán igual.

###### Análisis de Valores Límite
#Q 
- Es una **extensión** de la :: Partición de equivalencia.
- Solo se puede **usar** cuando :: La partición es ordenada y numérica.
- Los **mínimos y máximos** de... son sus... :: Partición de equivalencia, valores límite.
- **Niveles de prueba** a los que aplica :: Todos.
- Los **2 estilos que tiene** son :: 2 puntos y 3 puntos.
- Fórmula de Cobertura :: $\frac{\text{Numero de valores prueba probados}}{\text{Numero total de valores prueba identificados}} \cdot 100$

## Estándares
### ISO 9000
#Q 
- Nos da un **conjunto de normas** de... y de... :: Control de calidad, gestión de calidad.
- Estas normas son... y por eso se pueden **aplicar** en... sector orientado a producir... :: Genéricas, cualquier, bienes y servicios
- **Especifica** como organización debe operar sus... tiempos de... y niveles de... :: Estándares de calidad, entrega, servicio.
- Una de sus **principales ventajas** es la :: Mejora continua.

### ISO 12207
#Q 
- Nos da **sistema de procesos** para el :: Ciclo de vida de software.
- Contiene **3 cosas** :: Procesos, actividades y tareas.
- Los procesos, actividades y tareas son los que **deben aplicarse** siempre que se :: Se **adquiere** algo con software (producto, servicio, sistema).
- **Agrupa las actividades** que se pueden llevar a cabo en el ciclo de vida de software en :: Primarios (Desarrollo, mantenimiento, etc.), soporte (Documentación, auditorías, V&V, Revisiones, etc.) y organizacionales (Administración, infraestructura, entrenamiento, etc.).

### ISO/IEC 9126
#Q 
- Su **nombre** es :: Características de Calidad y Guías para su Uso.
- Nos dice que cualquier... puede ser **descrito** en una o mas de las... :: Componente de la Calidad del Software, **6 características** básicas.
- Estas **6 Características** son :: Funcionalidad, confiabilidad, usabilidad, eficiencia, mantenibilidad y portabilidad.

### ISO/IEC 14598
#Q 
- Proveen **métodos** para las... y... de la... de un producto de software :: Mediciones, evaluaciones, calidad.
- Da una vista de los... de un producto de software :: Procesos de evaluación.
- **Proveen** de cosas como... y requisitos de... :: Guías, evaluación.
- Se **usa por** :: Peritos, adquisidores y evaluadores independientes.
- También los resultados obtenidos nos pueden servir para **medir que tanto** se :: Acataron los requisitos.
